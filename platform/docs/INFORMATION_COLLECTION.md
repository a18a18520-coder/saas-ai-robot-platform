# 群消息信息收集机器人

## 微信桌面采集同步（0.6.0，本地开发已联调，未部署业务库）

插件直接调用现有租户登录接口，再通过 `/api/v1/tenant/collector/profile` 确认账号所属租户。账号需要消息权限；列出/关联群还需要群管理权限。临时密码仍须先在网页修改，动态角色、停用、会话版本和租户状态检查不绕过。

新增接口（全部在现有租户鉴权守卫下）：

- `GET profile`、`POST/GET devices`、`POST devices/:id/revoke`：绑定当前账号设备，管理员可撤销本租户设备，其他账号只能撤销自己的设备。撤销同步停用绑定，原安装标识不可自助恢复，历史原文保留。
- `GET groups`、`GET/POST devices/:id/bindings`：只列当前租户微信群，明确关联既有群或确认新建待绑定群。按设备和本地会话 ID 建立映射；群名称不作为身份键，已有映射不允许改归其他群。
- `POST devices/:id/messages`：服务器确定 tenantId/accountId，拒绝未启用绑定、停用群及撤销设备。强制单条 content、senderNickname、布尔 isSelf、identitySource、采集时间和依据摘要；不接收图片。来源 ID + 设备唯一，相同请求返回既有回执，不同正文/身份/绑定返回 409。
- `GET devices/:id/receipts?ids=…`、`GET messages?page=…`、`POST messages/:id/process`：回查归档与提取状态，浏览每页 50 条原文；未创建提取记录的原文可显式按当前已发布规则处理。提取仅投递已发布且发布快照为 collector 的机器人，不运行问答回复或工具。

数据库迁移 `1790000000024-CollectorSync` 新增 `collector_devices`、`collector_bindings`、`collector_messages` 和 `collection_records.sourceMetadata`。部署需先备份并核对全部待执行迁移，确认 21–23 号收集记录迁移已应用；本次仅在独立临时 PostgreSQL 验证，未修改正在运行的业务数据库。

租户端 `/t/collector` 展示群、原文、昵称、“本人”、操作账号、设备及提取状态；机器人收集记录保留相同昵称/本人元数据。“本人”仅表示采集时登录微信的账号。所有 OCR 来源标记 `identityVerified=false`，使用独立观察 ID，不因昵称或正文手机号自动匹配/合并平台用户，也不授予该观察者知识权限。截图采集时间不伪装成发送时间。

默认本地保存。插件只在指定会话明确开启同步后处理新截图；标准浅色文字气泡、高置信度和明确昵称/归属满足时自动投递；疑似/复杂/重复对齐不明先待核对。OCR 启发式无法保证事实准确性，附件、原生消息 ID、全量历史和跨设备精确去重仍不支持。建议一群仅一个采集设备，先用获准的合成消息做真机验证。

测试入口：采集仓 `npm run test:tenant-sync -- ../platform`（真实 HTTP + 服务/校验器，合成登录/仓储/模型）；`npm run test:tenant-postgres -- ../platform <独立临时数据库端口>`（仅固定的合成测试库配置）。界面隔离验收：前端 `node test/collector-ui.mjs`，只监听本机、不加载 .env、不代理业务 API。测试脚本不能代替真实渠道联调。

## 机器人配置入口

入口：租户端 → 机器人 → 新建“信息收集机器人” → 配置 → 收集规则。

配置工作模式、触发条件、收集提示词、业务约束和字段，使用一条样例消息测试，再“保存并发布”。在群管理中将目标群绑定到该机器人。模式、提示词、约束及字段均进入发布快照与版本历史；保存草稿不会改变线上行为。

## 当前能力

- 所有送达的普通群消息或仅 @ 消息，两种触发方式。
- 关键词预筛选（任一命中；留空则逐条交给模型）。未命中不消耗 AI 额度。
- 自定义收集提示词、约束、1–20 个字段；文本、数字、布尔类型；支持字段转换说明。
- 单条原文可提取多条结果，最多 20 条。缺少必填字段保存为“待核对”。
- 每个非空字段必须有原文逐字引用；服务端拒绝未知字段、错误类型和不存在的引用。
- 不执行群消息中的指令，不调用业务工具、不回复群聊、不触发转人工。
- 记录保留原文、发送人渠道 ID、来源消息 ID、群、采集时间、规则快照、结果、依据与状态。
- 原始消息 ID 去重；相同正文的新消息保留；失败/拦截记录可重试，超过五分钟的处理中记录可恢复。重试使用原始规则快照。
- 收集记录支持分页、状态筛选与本页 JSON 导出，受当前租户和机器人管理权限限制。
- 模型由平台统一分配，预览/采集/重试经过租户 AI 额度检查，模型调用计入“信息收集” Token 用量。

## 严格结构化字段（校验版本 3）

入口：收集规则 → 提取字段 → 输出校验方式 / 取值约束。自然语言提示词不能覆盖服务端硬约束。

| 配置 | 强制行为 |
| --- | --- |
| 严格模式（默认） | 文本值必须等于最小原文引用（允许去除引用首尾空格）；不能自由归纳 |
| 归纳模式 | 仍检查类型、范围、格式、枚举和真实引用，但所有非空归纳字段都列入 `reviewFields`，整条记录标记待核对 |
| 原文标签 | 只接受 `标签：值` 或 `标签:值`，用于减少人物、金额等字段串位；引用只包含值 |
| 文本 | 可指定长度、允许取值列表、绝对日期格式；不自动截断或替换非法枚举 |
| 日期 | 明确的 `YYYY-M-D`、`YYYY/M/D`、`YYYY年M月D日` 转为 `YYYY-MM-DD`；校验闰年，不推算明天、缺少年份 |
| 数字 | 单个阿拉伯数字及精确配置的原文单位；输出等于原数 × 转换倍率；校验转换后上下限、整数、安全范围和精度 |
| 布尔 | 依据必须精确匹配“是/否”的原文取值列表（默认是/true、否/false）；不能从“不是”中截出“是” |

例如“金额：1.2万元”：数字类型、原文标签“金额”、原文单位“万元”、倍率 10000、上限 50000，输出 12000；上限改成 10000 后整条提取失败，不会截成 10000。严格数字不接受中文数字、范围、约数或暗中进行的四舍五入。数字和布尔依据必须是独立取值，不能截取其他数字或否定表达的一部分。单位与格式不支持的表达应返回 null，不能猜测。

版本 3 加强取值边界：带标签的严格文本不得把“负责人：张三丰”截成“张三”，不能从其他位置借用合法的结束边界。日期不得截去“晚上”“至25日”等限定，布尔值不得截去后续词语。固定模板建议用分号或换行分隔字段；不支持的表达返回 null，归纳需求明确选择 review 模式。此检查不证明复杂语义或跨字段关联正确。

协议同时要求：所有配置字段显式返回（未知值为 null），只接受声明的属性、正确 JSON 类型，不接受重复 JSON 键、重复记录、无效日期、不安全数字和超大/过深响应。一个字段不合格时整条消息的模型结果不予接纳，`items=[]`，状态为 failed；保留安全的 `validationErrors`，包含错误码、字段、结果下标（从 0 开始），不展示未经校验的模型原始输出。预览与落库执行同一校验器。

缺少必填值或含归纳字段时为 needs_review，不与 collected 混用；页面显示具体待补充或待核对字段。当前没有自动审批/确认流程，需人工核对原文。严格校验不是业务语义真实性证明：例如跨人物关联、否定/假设的复杂语境仍需人工确认；重要字段建议使用固定“标签：值”模板。

版本 2 的历史迁移保留原文和结果，把此前的 collected 记录改为 needs_review、校验版本保留为 1，不把旧结果冒充严格校验成功。旧配置不指定 rules 时默认为严格模式；旧的自由归纳规则需要明确改为“归纳”并重新发布。重试仍使用原规则快照；如需要修改规则，先用“测试提取”验证新草稿，再发布以处理新消息，不会偷偷用新规则改写旧结果。

版本 3 迁移仅更新新记录的数据库默认校验版本，不改写既有记录、原文或状态；新结果与显式重试使用版本 3。版本 1/2 的历史结果仍保留原版本，不代表已经通过版本 3 的边界检查。

## 能力边界

第一版按单条文本提取，不跨消息、跨人、跨群推断，不识别附件或自动写入其他业务系统。字段依据校验可以发现没有来源的引用，不能证明所有语义判断正确，业务上仍可核对原文。

群目前是一群一机器人；绑定收集机器人后，这个群使用收集流程，不同时运行客服问答。

渠道必须实际投递消息：钉钉标准机器人群消息仅在被 @ 后投递，HTTP/Stream 切换不能扩展这个范围。微信普通群消息需要本地采集插件，本次增加的平台能力不包含微信客户端插件安装或采集实现。其他渠道依实际授权与消息事件能力而定。

钉钉官方说明：https://opensource.dingtalk.com/developerpedia/docs/explore/tutorials/stream/bot/go/test-bot/

## 采集端接入约定

现有认证入口 `POST /api/v1/tenant/messages` 支持信息收集消息。使用租户认证，不能从请求指定其他租户；调用账号需要消息功能权限。目标群必须已登记且绑定到已发布的信息收集机器人。接口不会自动创建群。

```json
{
  "channel": "wechat",
  "channelId": "采集账号或渠道的稳定标识",
  "chatId": "目标群的稳定标识",
  "channelUserId": "发送人的稳定标识",
  "sourceMessageId": "该来源消息的稳定唯一标识",
  "isAtRobot": false,
  "content": "故障上报：设备编号 DEVICE-DEMO-17，屏幕无法点亮。"
}
```

`sourceMessageId` 在重试中必须保持一致，不可每次轮询重新随机生成，也不能仅按正文哈希产生；不然会重复计量或丢掉合法的重复上报。平台按租户、机器人、渠道、渠道账号、群、消息 ID 去重。没有稳定消息 ID 的收集输入会被拒绝。

同一去重范围内，来源 ID 对应的正文和发送人必须与初次接收一致；冲突返回 HTTP 409，原记录不覆盖，也不重复扣减额度或调用模型。消息编辑需要单独设计带版本的更新协议，不可冒充普通重试。

响应包含 `collectionId`、`collectionStatus`，不含可向群发送的 `answer`。记录状态：processing、collected、needs_review、ignored、failed、blocked。采集时间是平台接收时间，不冒充微信原始发送时间。

管理接口（当前租户机器人权限）：

- `GET /api/v1/tenant/robots/:id/collections?page=1&status=collected`
- `POST /api/v1/tenant/robots/:id/collection-preview`：`{ config, content }`；不保存结果、不发送消息。
- `POST /api/v1/tenant/robots/:id/collections/:recordId/retry`

## 验证

数据库迁移：`npm run migration:run`（backend 目录）。收集表及严格校验迁移不修改既有机器人配置。

单元回归：`npm test -- --runInBand collection robots.controller`。

已部署服务合成验收（推荐）：backend 目录运行 `node test/collection.deployed.cjs --allow-local-fixtures`。默认访问 `http://127.0.0.1:5175`，要求本机数据库和相邻目录 `wechat-collector`；可通过 `COLLECTION_TEST_ORIGIN`、`COLLECTOR_PROJECT` 调整本机测试地址和采集助手路径。脚本创建随机标识的临时套餐、租户、账号、权限角色和本机模型配置；账号通过正常密码登录，随后使用真实发布、群绑定、消息提交和记录查询接口，采集助手使用真实 Store/Uploader。模型仅为回环地址上的固定响应服务，不调用收费模型。

此测试会短暂写入数据库中的合成数据；成功或异常结束时按本次随机 UUID 清理，不使用任何已有租户。正常结束输出 `CLEANUP`，并核对租户范围记录和套餐、模型、租户均无残留。不要用强制终止进程代替等待清理；进程崩溃、断电或数据库不可用时不能保证自动清理。

事务集成：`node -r ts-node/register test/collection.integration.cjs`。

真实模型验收：`COLLECTION_LIVE_TEST=1 node -r ts-node/register test/collection.integration.cjs`。使用合成设备故障、金额/日期/布尔消息，事务内暂时延长套餐并重置测试额度，结束时回滚租户变更、机器人、群、结果和用量记录；真实模型服务仍可能计费，不向任何群发消息。

隔离界面验收：frontend 目录运行 `node test/collection-ui.mjs`，打开 `http://127.0.0.1:5186/test/fixtures/collection.html`。仅绑定本机，不连接生产 API、数据库或真实模型，合成模型响应经过真实后端校验器。验证默认金额转换成功，再将上限改为 10000，预览应清空并显示越界错误；结束后停止该临时进程。此页面不进入生产构建，不代替真实登录与渠道端到端验收。
