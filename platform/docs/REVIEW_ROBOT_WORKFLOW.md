# 审核机器人流程契约

状态：已确认业务设计；结果校验核心已实现，尚未接入生产接口、任务持久化和 Dify 工作流。不能据此认为审核功能已经上线。

## 配置与边界

平台绑定租户审核机器人的 Dify 工作流及租户模型。租户配置业务场景、规则知识库、工具授权、人工审核人员，以及人员/工具结果出口。工具声明输入输出协议。不得复用客服工作流中的会话记忆。每个审核任务单独上下文。

## 编排节点

1. 平台鉴权并校验工具绑定：由身份确定租户，不能信任请求中声明的租户。业务请求号与内容版本组成幂等标识；同标识不同内容拒绝覆盖。
2. 固定待审内容、机器人已发布配置及工作流版本。保存任务后异步执行，避免请求断开丢任务。
3. Dify 开始节点接收 task_id、content、content_version、审核场景和授权规则范围；待审文本属于数据，不得作为系统指令。
4. 检索知识库规则：只允许本租户授权范围，返回规则编号、库/文档/切片标识、版本和原文。授权与规则证据必须由平台可信检索通道验证，不能信任模型生成的引用字段。
5. 无规则、检索失败、材料缺失、规则冲突：进入人工分支，不能放行。
6. 分项审核：输出 decision、summary、findings；每项包含 ruleId、ruleQuote、contentQuote、explanation。通过也需要列出依据；结果结构校验不等于已证明判断正确，仍需标注样本检验漏判和误判。
7. 平台运行 review-contract 校验。非法格式、无效证据统一进入人工队列；人工工单保留原因和已有结果。
8. 人工补充/裁决产生新结果版本，记录审核人员和依据；不能覆盖审计历史。
9. 事务内生成两个独立发送任务：人员出口和工具出口。只重试失败的出口；不确定是否送达的写入型接口需先对账，不能盲目重发。

## 结果契约

机器判断：passed、rejected、needs_information、human_review。
任务执行状态与业务判断分离：awaiting_human 不等于 rejected。
对人员用可读摘要，对工具按声明映射，但不得改变原始结论。
缺少材料和需要复核时保留模型说明，不伪装成接口故障。

## 下一步集成验收

- 数据迁移：审核任务、规则快照、人工处置历史和双出口投递记录。
- 持久队列：服务重启后恢复执行，超时进入人工；明确重试次数和模型切换策略。
- API：鉴权提交、任务查询、人工处理和发送结果核对；禁止未认证公开入口。
- 回调：使用已配置工具地址而非用户任意 URL，复用请求地址安全校验及凭据管理。
- UI：机器人审核配置、人工审核任务、状态与投递异常处理；沿用现有视觉规范。
- Dify：发布独立工作流并校验知识授权，使用实际规则库联调。
- 验收：跨租户拒绝、无规则转人工、伪造引用拒绝、内容变更重新审核、重启恢复、双出口独立失败重试、人工裁决后最终返回。
