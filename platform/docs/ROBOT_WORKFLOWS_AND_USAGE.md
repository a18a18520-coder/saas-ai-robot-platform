# 机器人工作流与 Token 统计

## 工作流建议（尚未实现执行适配）

继续用 Dify 编排和执行工作流。租户侧提供机器人绑定、触发条件、输入映射、输出映射、授权和运行记录，不复制一套工作流引擎。当前 workflowId 仅保存绑定，不能当作已完成调用。

平台管理员分配工作流资源和服务器端密钥；租户只能选已授权资源。执行前检查租户、机器人发布快照、用户角色与允许工作流。禁止模型任意传入工作流 ID、URL 或密钥。工作流输入只包含本次问题、当前会话允许的上下文和已授权证据；不得读取其他会话。输出经过来源、权限与长度检查再进入回答。

需补接口：工作流服务器端 API Key（加密）、输入输出契约、published binding、工作流执行器、运行状态/错误恢复与审计。工作流里的模型配置必须从平台授权配置发布，不能认为机器人主备模型设置会自动覆盖 Dify 节点。

主模型的三次重试仅适用于模型请求。含外部写操作的整个工作流不得因模型失败自动重跑，以免重复下单或写入；需节点级幂等和人工确认策略。

Dify 返回 workflow_run_id 和总 Token。执行链路接通后以 tenantId + workflow_run_id 唯一记账，不能把工作流总量与节点总量相加。只有总量时输入/输出仍为未知；失败运行也应查询最终用量。参考：https://github.com/langgenius/dify/blob/main/api/controllers/service_api/app/workflow.py

## 本次已实现的统计代码

- 机器人配置页提供累计、本月、历史月份和调用环节统计，月份按 Asia/Shanghai 的请求开始时间归属。
- GET /api/v1/tenant/robots/:id/token-usage：签名租户上下文、机器人归属检查、所有聚合再次按租户和机器人过滤。
- robot_model_usage 按真实模型请求记账，含模型、环节、重试序号、备用标识、成功状态及输入/输出/总 Token。
- 覆盖直接调用的回答、改写、摘要、工具选择、重排、评测评分；评测产生的回答等请求也计入机器人用量。
- 缺失 usage 记为未知；已消费 Token 的截断回答仍计入。缓存/推理明细不重复相加。统计不是服务商账单。
- 记录写库异常会记服务日志，不触发模型重试；数据库故障时可能漏记，尚无持久化对账队列，因此不能用于财务计费。
- 历史用量不可凭消息长度回填。未接通的 Dify 工作流、知识入库 Embedding 用量不包含在本次统计中。

## 启用及验证

需执行数据库迁移 1790000000003-RobotTokenUsage；无迁移时统计会明确加载失败，不显示虚假零用量。
单元测试覆盖用量缺失、截断、超时、租户隔离、SQL 月份时区及记账失败隔离。真实数据库迁移和带模型请求的端到端验收仍需运行环境。
