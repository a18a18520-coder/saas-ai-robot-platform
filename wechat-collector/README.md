# 微信信息采集助手

面向 macOS 与 Windows 的独立桌面采集项目，当前版本 **0.6.0 租户同步版（本地测试版）**。源码独立实现，没有复制 ChatScreenExporter 的源码、图标或 UI 资源，也不依赖其程序。0.3.0 当前会话的 Mac 真实采集、加密落盘和切群暂停已通过；新版自动分割、真实滚动和双群轮巡仍需微信真机验收，见 [公开验证摘要](../VALIDATION.md)。

## 已实现与边界

- 0.6.0：插件直接登录租户账号，服务端确认租户/操作账号后注册设备。每个会话明确选择租户已有微信群或确认新建；开启同步后，只处理新采集画面。满足已确认浅色气泡布局、昵称和高置信度条件的文本进入自动同步，其他候选先核对。每条记录携带昵称、单条正文、本人标记及来源摘要；不会将昵称或正文中的手机号自动合并为平台真实用户。
- 同步队列按平台地址、租户、账号、设备隔离；登录凭据仅在内存，不保存密码。退出/登录失效停止新请求；网络失败保留原消息 ID 重试，冲突不覆盖。平台群名和提取回执可回查；租户端 `/t/collector` 查看原文、设备和状态并撤销设备。业务服务仍须升级后端/前端并应用新迁移后才能使用，旧服务不会自动获得新接口。
- 0.5.1：已满足的权限步骤收起，开始/暂停固定在底部；未就绪时明确显示原因，“去设置”定位到缺少的配置。旧会话不再自动选中，需主动选择或新建绑定；不误把上次配置当作微信当前聊天。次数上限仍折叠，间隔与滚动并排。轮巡重新校准走完整引导，断开时解除绑定中的界面锁定；不自动授权或采集。

- Windows 窗口组件改为随包自带的原生 EXE；运行时不调用 PowerShell，不需要安装 Node/Python/.NET 或编译器，不自动提权、不修改系统策略。原生规则在合成驱动器中验证，Windows 实际窗口、缩放与输入仍待真机验证，不能仅凭构建成功承诺适配。
- 打包前检查本机组件的源码/二进制哈希、协议版本、架构及第三方声明；缺失或过期时中止打包，不把半成品交给使用者。取消后的迟到响应、异常尺寸、窗口身份不一致和未知协议响应全部拒绝。
- 面向非技术用户的三步主流程：系统权限 → 选择单个会话或多会话轮巡 → 设置频率与滚动。常规操作不需要终端、平台账号、API 密钥或手填坐标；自动找到唯一可见微信窗口，多窗口时请用户选择，不自动开始采集。
- 首次设置临时放大助手预览，框完会话名后提示框消息区，填写完整会话名并通过严格校验后回到紧凑侧栏。保存第一张原文后收起引导，让原文留在主要位置。仍需首次手动框选，不承诺全自动识别任意微信版本布局。
- 微信重启导致窗口 ID 改变时，可显式“校验并恢复此会话”；原群身份、标题指纹、OCR、画面及原生窗口尺寸必须一致，取消/失败不写入。尺寸/标题变化仍需重新设置，不以模糊匹配绕过。
- 可直接查看截图数量、最近采集时间，并导出所选会话的未核对 OCR 原文；不再必须先创建人工核对消息才能导出文字。导出不含截图、不是单条消息、不会推算发送人/发送时间，文件为明文。
- 用户显式选择窗口并框选聊天区域，不请求麦克风或摄像头，不采集整台电脑。
- 独立紧凑侧栏：浅灰背景、绿色操作按钮；默认当前会话，突出开始/暂停和最新原文，校准、历史与核对记录折叠。不是微信内部插件，不注入微信进程。
- 显式连接预览后可“贴靠微信”：优先右侧、左侧回退，每 1.5 秒检查位置；空间不足时解除贴靠并暂停，不覆盖聊天或移动微信。
- 单会话支持不滚动、向上读取有限历史（1–30 屏，含当前屏）、向下定时跟进；间隔 2–3600 秒，本轮 1–50 次，0 表示持续至暂停。向上模式到屏数/次数上限或画面不再变化就停止，不自动返回底部；向下模式每次识别后等待间隔再滚动，不保证一次到最底部。单会话绝不自动切群；滚动需单独确认和系统控制权限。
- 中文简体与英文 OCR 在本机运行，语言模型随安装包携带，不把截图发送给云端模型。
- OCR 在独立进程运行，60 秒超时覆盖语言模型初始化和识别；停止会终止当前任务，迟到结果不保存。旧进程未确认退出前不会创建新进程，避免连续重试堆积任务。
- 每次采集保存独立截图和原始识别文字；人工分别核对单条消息、群、发送人及原始时间标签。
- 不从昵称猜测身份，不把截图时间当作发送时间，不用相似度去重删除业务消息。不确定的发送人、时间保留空值。
- 本地数据使用 macOS Keychain / Windows DPAPI 通过 Electron safeStorage 加密；加密不可用或旧文件不能读取时停止写入，不降级为明文。加密不能防御当前用户身份下的所有恶意程序，也不替代磁盘加密或设备访问控制。
- 已核对记录可显式导出 JSON。JSON 是明文，包含原始 OCR 和核对后正文，但不包含截图。
- 可手动提交到已有 SaaS 平台的 `POST /api/v1/tenant/messages`；默认不上传。使用本次会话中的租户令牌，令牌不写入文件。只允许 HTTPS 或本机 HTTP；禁止重定向。
- 投递重试保持同一个本地消息 ID。相同正文的独立记录保留并提示人工核对。
- 多群串行轮巡：每群分别校准标题、左侧会话入口和消息区域，首次历史默认 10 屏（0–30 可配），随后按 10–3600 秒间隔检查新增画面。各群配置、历史进度、截图归属和核对记录分开保存。
- 双重标题校验：OCR 核验完整群名，并与校准时的标题区域 PNG 指纹一致。群名不符、标题变化、低置信度、尺寸变化、遮挡、权限失效等错误会暂停对应群；所有群暂停则结束轮巡。不使用模糊匹配继续采集。
- 原生控制组件只接受指定微信窗口的点击/滚动操作，不含键盘输入、发送消息或数据库读取。Mac 使用辅助功能权限，Windows 检查窗口进程/前台状态。可随时点“停止轮巡”或按 Mac `⌘⇧X` / Windows `Ctrl+Shift+X`。

**仍有限制**：自动分割仅支持保守的浅色标准文本气泡规则，不保证任意微信版本、主题、DPI、图文卡片或跨屏消息精确对齐。缺少连续画面锚点、重复内容和归属不清进入待核对；复杂内容可能只生成整屏核对入口，需要逐条补录。没有微信原生消息 ID，不能保证跨设备去重，不建议两设备同时采同一群。无无人值守后台全量采集、附件识别、一次性码配对（按用户选择改为账号登录）或永久登录。多群轮巡是前台有限滚动，不是微信后台消息接口。

## 0.6.0 租户登录与同步操作

1. 平台先部署对应后端/前端与 `1790000000024-CollectorSync` 迁移；它依赖现有收集记录表及 21–23 号相关迁移。部署前备份、核对 `migration:show`，不要不经检查直接应用工作区所有未执行迁移。本次只在独立临时 PostgreSQL 验收，没有修改业务数据库。
2. 在助手展开“租户同步”，输入**后端服务地址**（不是前端页面 URL）、租户账号和密码。账号需消息权限，首次关联群还需群管理权限。HTTP 只允许 localhost/127.0.0.1；远程服务须 HTTPS。临时密码账号需先在网页修改密码；不要在聊天中提供密码。
3. 按原三步流程完成本地微信会话绑定。回到“租户同步”点“刷新群与回执”，选择本地会话、租户已有微信群或“新建租户群”，检查所属租户和目标群。已有绑定不能改归另一群；确需更换时建立新的本地会话配置。
4. 需要自动识别本人消息时填写**本人微信昵称**，不是租户登录账号。确认浅色标准文字气泡规则后可启用自动识别。勾选本会话同步及数据范围确认并保存；设置会折叠。没有勾选布局确认时，消息候选全部待核对。
5. 开始采集。疑似消息点“核对原文”，逐条核对昵称、本人/对方、正文和原始时间标记；无法确认就不提交。一次只核对一条，同一截图还有其他消息可“同图补录另一条”。时间标签不转换成推测的发送时间，采集时间另存。
6. 开启同步且登录有效时，每 10 秒最多处理 20 条待发送记录，回查最近 50 条已同步记录的提取状态。群列表最多读取 500 个、设备列表最多 100 个。平台接收原文不代表提取成功。新建群初始待绑定；到租户“群管理”绑定已发布的**信息收集机器人**（触发方式设为全部消息），再在“微信采集”点击“按当前已发布规则处理”。严格字段规则仍由服务端执行。
7. “暂停”只暂停截图采集。停止消息同步请取消会话同步并保存，或退出登录。已经到达平台的请求不会被撤回。设备撤销同时停用其绑定且不能用原安装标识自行恢复，历史原文保留；当前版本没有设备恢复授权入口。

截图仍只保存在本地加密文件；上传的是昵称、单条正文、本人标记、采集时间、图片哈希与识别依据摘要。昵称/本人是观察信息，不是认证过的微信身份。队列另限 500 条；“导出记录与同步队列”会导出所有本地账号范围的记录（明文、不含截图），清空前请自行保管必要证据。

只有屏幕上实际渲染、可捕获的消息才可能被识别。微信窗口标题可能不随切群变化，因此仅凭窗口 ID 不能证明群身份。当前会话模式监测聊天标题区域，每次消息识别前再次核验；仍建议切群前主动暂停，切群后重新选择并确认。多群模式必须先逐群校准，不得在运行中手动切群。窗口不可用、锁屏、权限撤销或尺寸改变时应重新选择；不能保证隐藏、最小化窗口的完整性。

## 普通使用者：无需开发环境

1. 从发布者处取得与你系统匹配的包。Mac Apple Silicon 选择 `arm64.dmg`，Intel Mac 选择不含 `arm64` 的 DMG；打开后将应用拖入“应用程序”。Windows ZIP 需完整解压，双击其中 `WeChat Collector.exe`，不能只移动 EXE。Windows 安装器应由 Windows 构建机生成后再分发。
2. **第 1 步：系统权限。** Mac 点“录屏权限”，由本人授权后重开助手；如需滚动或轮巡，再点“滚动与切群权限”。若主应用已获授权但组件未授权，展开帮助并“定位需要授权的控制组件”，在系统设置中手动确认。点“重新检查”。不滚动可跳过控制权限。Windows 在连接所选窗口后核验，不自动提权。无需微信密码、摄像头或麦克风权限。
3. **第 2 步：选择会话。** 在微信打开允许处理的聊天，选择“单个会话”，点“连接微信窗口”→“绑定当前打开的聊天”。依提示框住顶部完整会话名和消息区，填写真实完整名称，点“确认并绑定”。这会建立新绑定，不会把旧的“示例群”等配置改成新聊天。以后使用“已绑定会话”选择；窗口重启可“校验并恢复连接”，范围变化用“调整采集范围”。下拉选项不是微信当前聊天的实时识别结果，切换微信不会自动跟随。
4. **第 3 步：频率与滚动。** 设置间隔（默认 10 秒），选择“不滚动”“向上读取历史”或“向下跟进消息”。向上可设屏数上限；更多次数设置默认持续。不滚动只需会话确认，滚动还须确认允许前台控制。点击“开始采集”；也可“先采集一张”。看到本地截图数和最新原文才算成功，连接预览不等于已采集。多会话轮巡操作见下文。
5. 原文可直接看或导出。默认不会上传；启用 0.6.0 租户同步后按上节规则处理。切群/锁屏/窗口失效会暂停采集，不能在后台监听所有会话，也不向微信发送消息。

**分发状态**：当前包是未配置正式发行签名/公证的测试包，不是可向所有用户承诺“下载无提示即用”的公开正式版。Mac 录屏授权必须由使用者本人确认；遇到系统安全拦截不要关闭保护或删除隔离属性。正式分发需完成 Apple Developer ID 签名/公证、Windows 签名及 Windows/Intel 真机测试。0.4.1 已移除运行时脚本依赖，但 Windows 应用控制或企业安全策略仍可能拦截未签名 EXE；应联系管理员审核，不得绕过。

## 启动开发版

需要 Node.js 22.12 或以上、npm；Mac 窗口检查/控制组件要求 macOS 13 或以上（包括当前会话模式），源码构建需要 Apple Command Line Tools（`xcrun swiftc` / `clang++`）。首次安装需要网络下载依赖；运行时 OCR 不需联网。

构建 Windows 版本时，`scripts/toolchain.cjs` 在 `.runtime/toolchains/` 准备固定版本 LLVM-MinGW 20261020，并校验上游发布资产的 SHA-256 后才解压执行。编译器仅用于构建，不进入安装包；最终 EXE 静态链接 C++ 运行库，仅依赖 Windows 系统 DLL。目标为 Windows x64（需要支持 PerMonitorV2 的现代 Windows）；不支持 Windows 7/8，不将本机交叉编译当作 Windows 真机兼容性结论。

```sh
cd "wechat-collector"
npm ci
npm start
```

Windows 在项目目录打开 PowerShell，执行同样的 `npm ci`、`npm start`。不要照抄上面的 Mac 绝对路径。

## 操作流程

1. 登录自己的微信，打开有权处理的目标聊天。首次使用 Mac 可能需要在系统设置的“隐私与安全性 → 屏幕与系统音频录制／屏幕录制”中允许本应用，然后重启。单群截图不需要辅助功能控制；多群切换/滚动需要另行明确授权辅助功能。
2. 主流程点“连接微信窗口”；有多个候选窗口时，在“会话绑定与高级设置”选择目标并“连接预览”。连接不等于开始采集；可点击顶部“贴靠微信”，旁边需要足够桌面空间。
3. 点“绑定当前打开的聊天”，依引导选择**顶部完整群名**和**消息区域**。高级设置仍保留坐标输入。填写实际完整群名后“确认并绑定”。单个会话不需要左侧入口；多会话轮巡才需要。冻结图只用来定位，后续从实时画面取区域。
4. 顶部保持“单个会话”，选择已绑定会话，在第 3 步设置频率/滚动并确认后开始。“暂停”结束任务；高级设置的“断开预览”还会释放窗口流和解除贴靠。暂停、切换目标或修改设置后需再次确认才能开始。
5. “最新原文”只显示所选会话的最新截图 OCR，截图数不等于消息条数。点击“核对原文”，对照图片填写一条消息，确认目标群与发送人。OCR 有错可人工修正，原始 OCR 会另行保留。
6. 勾选核对确认，点击“保存为已核对消息”。同一截图多条消息需分别核对。修改内容后会取消之前的确认，防止误保存。
7. 点击“导出记录与同步队列”显式选择保存路径；旧版兼容入口也可在填写平台绑定 ID 和连接参数后逐条点击“提交平台”。

本地最多保留 50 张截图、500 条核对消息且总 JSON 不超过 60 MB。达到上限时需先导出必要数据，再显式清空。清空不可撤销，导出不含截图；需要保留截图时不要清空。应用不会按年龄自动删除截图。

## 多群轮巡配置

1. 连接微信窗口，把需要采集的群入口保持在左侧会话列表中可见且位置稳定；建议用户自行置顶。应用不会替用户修改置顶状态。
2. 选择“多会话轮巡”，手动打开第一个目标群，确保顶部完整群名可见（不是省略号）。点“添加当前打开的会话”。
3. 按引导依次框选**顶部完整群名**、**聊天消息区域**、**左侧该群入口**。消息区域应排除输入框；标题框尽量只包含文字和成员数。高级设置仍支持像素坐标输入。
4. 填写完整群名并“确认并绑定”。平台 ID 可不填。标题 OCR 识别失败时不保存，也不强行降级为模糊匹配；应调整窗口/区域后重试。
5. 手动打开另一群，再点“添加当前打开的会话”，重新框选三个区域并保存。不得把前一群的入口坐标直接当作后一群入口。
6. Mac 在第 1 步完成控制组件授权，连接后点“检查所选窗口的控制权限”。仅给主应用授权不代表控制组件已获授权；仍未通过时在授权帮助中定位组件，由本人在系统设置添加/开启，再重新检查。检测未通过时不能启动轮巡；应用不会修改权限数据库。屏幕录制与窗口控制是不同权限。
7. 切换到“多会话轮巡”。逐个手动打开聊天，点“添加当前打开的会话”，依次框选标题、消息和左侧入口并保存；旧的两区域绑定需用“调整采集范围”补齐入口。勾选本轮目标（默认空），在第 3 步统一设置间隔（至少 10 秒）和首次历史上限（0–30 屏），确认允许切换与滚动后点“开始轮巡”。只在一个选定微信窗口内依次切换多个会话，不同时轮巡多个独立窗口。运行时会占用微信前台，不要同时操作鼠标。全局快捷键 `⌘⇧X` / `Ctrl+Shift+X` 可停止；快捷键注册失败则不启动。
8. 查看每行的状态/截图数，点击“查看内容”按群筛选。在“待核对截图”中选择截图查看原图和 OCR；截图不是自动分割好的单条消息，需要人工逐条核对。

### 轮巡边界与恢复

- 标题 OCR 可能把表情误识别成汉字。校准失败会显示预期群名、识别文字与置信度；不能把错误识别文字改填为群名，也不能降低匹配要求绕过。此类标题兼容性仍待修复和真机验证。

- 默认 10 屏包含首次读取的当前画面，最多向上滚动 9 次；0 表示不向上。每步保留重叠区域，因此不是 10 个完整无重叠屏幕，也不是“最近 10 条消息”。从**进入该群时显示的位置**开始，不保证微信自动定位到最底部。
- 读历史后按相同次数向下返回，随后每次访问最多再向下检查 10 步。画面哈希相同时提前停止；每个群访问结束后才计时等待下轮，OCR 较慢时实际间隔会更长。
- 只抑制同群相同截图，不按正文删除消息，也不能保证跨屏同一条消息精确去重。两群相同截图哈希仍分别保留。
- OCR 的标题文本规范化会忽略空白、装饰 emoji 等差异，所以同时强制标题区域指纹一致；不能只凭规范化文字确认群。标题人数、主题、字体或布局变化也可能导致安全暂停，需要人工核对并重新校准。无法区分的同名配置不允许同时保存。
- 群入口被新消息排序移动时，可能切到其他会话，但在标题校验通过前不保存其消息。重新校准前先停止轮巡。重启微信导致窗口 ID 改变后也需全部重新校准。
- 单群错误不会挪动其数据到其他群；已保存截图中的群名/配置 ID 和已知平台绑定不可改写。未绑定的平台 ID 可在人工核对时补填，原始截图归属快照保持不变，不自动推断。
- 历史已完成标记跨应用重启保存；中途失败不会误标完成。明确“清空本地数据”会重置历史进度，但保留群配置。容量满后安全暂停，不自动删除或覆盖原文。
- 本地加密文件中分别关联群 ID，并非每个群单独一个物理文件；列表筛选不会改变原文或记录归属。

## 旧版手动令牌接口（兼容入口）

下述为旧版高级手动提交方式，不携带 0.6.0 新增的昵称/本人元信息。新用户使用上方“租户同步”，无需填写下述绑定 ID 或令牌。

目标群必须已经在平台登记且绑定**已发布的信息收集机器人**，调用租户须有效且具有消息权限。以下 ID 由平台绑定关系提供，不允许用模型生成，不能用昵称冒充平台用户身份。

```json
{
  "channel": "wechat",
  "channelId": "登记的采集账号标识",
  "chatId": "登记的群标识",
  "channelUserId": "登记的发送人标识",
  "sourceMessageId": "local:持久化UUID",
  "isAtRobot": false,
  "content": "人工核对后的单条消息"
}
```

本地 UUID 标识“核对记录”，不是微信原生消息 ID。它可保证同一记录重试幂等，不能自动解决两次截图把同一条消息重复录入的问题。正文重复提醒不自动删除记录。

平台必须返回 `collectionId` 和 `collectionStatus`，状态限于 processing、collected、needs_review、ignored、failed、blocked。错误结构／问答回复不被当作收集成功。界面显示的是提交时返回的状态快照；失败结果应在平台收集记录中按其规则重试。本轮只进行了合成接口测试，未连接真实租户上传。

同一来源 ID 重试必须保持正文与发送人一致。平台返回 HTTP 409 时不会覆盖原记录，采集端会明确提示冲突；不要通过换一个 ID 强行重发。空响应、非 JSON、业务错误码和异常响应包装均不标记为已送达。

## 构建与测试

```sh
npm run check
npm test
npm run test:native
npm run smoke:ocr
npm run smoke:native
npm run smoke:desktop
npm run test:platform -- "../platform"
npm run test:tenant-sync -- "../platform"
npm run build:mac
npm run build:win
```

Windows 默认输出 ZIP 解压运行包。需要 NSIS 安装器时，在 Windows 构建机运行 `npm run build:win:installer`。本机 Apple Silicon Mac 生成 NSIS 安装器时遇到工具架构不兼容，因此不将该安装器标记为已完成。

默认输出目录：`dist/`。0.6.0 测试包使用独立目录 `dist/v0.6.0/`，保留旧版本，不覆盖其运行文件。构建配置支持 Mac 两架构和 Windows x64 ZIP，Windows CI 包含原生规则测试与 NSIS 安装器构建步骤；没有自动发布。两种操作系统须分别完成权限、捕获、DPI、恢复、加密存储与卸载验收。具体实际构建/测试结果见验收记录，构建成功不等于真机运行通过。

Windows 组件变更后必须执行 `npm run resources:win`；Mac 执行 `npm run resources`。可分别运行 `npm run check:native -- --win` 或 `npm run check:native` 检查构建凭证；直接调用 electron-builder 时也会执行同一打包前检查。不要把旧版本组件手动复制进新包。

构建后运行 `node scripts/package-verify.cjs "安装包解压目录或 .app 路径"`，逐文件核对真正进入应用的源码、原生组件、许可与离线 OCR 数据，防止测试源码与交付包不一致。`smoke:native` 仅向实际组件发送 6 组无效参数，确认拒绝路径；不操作真实窗口，不能替代系统权限或真实输入验收。

没有配置发行签名或 Apple 公证。正式分发前需要签名／公证及更新策略，不建议用户关闭系统安全机制。不要自行移除来源隔离或禁用安全提示。

`test:platform` 需要指定已安装依赖的 SaaS 源码仓库，启动临时本机 HTTP 服务，使用平台真实控制器、权限守卫、消息路由、响应包装和字段校验器。身份验证结果、仓储、额度及模型均为合成替身，不导入 AppModule、不读取 `.env`、不连接数据库、不调用真实模型；结束后清理临时文件。它不替代真实 JWT 登录、PostgreSQL 或渠道联调。

OCR 进程监督按 [Electron utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process) 的消息及退出事件实现；只有收到退出事件才允许替换旧进程，不把发出停止请求等同于已经退出。

界面隔离验收：`npm run preview` 后访问 `http://127.0.0.1:5188`。内置甲/乙两个合成会话，连接合成微信预览后可测试当前会话、切换后暂停、独立原文与白名单；顶部测试按钮只切换合成画面。也可导入合成截图测试人工核对。此服务只监听本机，不读取微信、不落盘聊天、不连接平台；调用真实核对校验函数。结束后 Ctrl+C 停止。

首次使用验收可在 Mac 终端运行 `COLLECTOR_PREVIEW_EMPTY=1 npm run preview`，从没有已保存会话的状态开始。此模式仅验收引导交互，不能替代真实 OCR、权限或安装验收。
